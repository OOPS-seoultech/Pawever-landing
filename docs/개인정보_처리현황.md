# 개인정보 처리 구현 현황

## 1. 수집 목적과 항목

### 앱 회원

자체 가입은 없고 카카오·네이버·애플 로그인만 있습니다. 수집 경로가 둘로 갈립니다.

**(1) 소셜 로그인 시 제공처에서 받아오는 항목**

| 제공처        | 구분 | 항목                                                |
| ------------- | ---- | --------------------------------------------------- |
| 카카오·네이버 | 필수 | 이름, 휴대전화번호, 연령대                          |
| 카카오·네이버 | 선택 | 이메일, 성별, 생일, 출생연도, 닉네임, 프로필 이미지 |
| 애플          | —    | 이메일만 제공. 이름·전화번호는 받지 않음            |
| 공통          | 필수 | 소셜 회원번호 (애플은 연동 해제용 토큰도 함께 저장) |

- 선택 항목에 동의하지 않으면 빈 값으로 저장됩니다.
- 애플로 가입한 회원은 이름·전화번호가 비어 있습니다.
- 목적: 회원 식별, 중복 가입 방지, 통계 분석

**(2) 앱에서 이용자가 직접 입력·설정하는 항목**

| 항목                               | 구분 | 비고                                                              |
| ---------------------------------- | ---- | ----------------------------------------------------------------- |
| 이름, 닉네임, 휴대전화번호, 연령대 | 필수 | 받아온 값을 수정. 애플 가입자는 여기서 첫 입력                    |
| 가입 경로                          | 선택 | 주변 추천 / 쓰레드 / 인스타그램 / 오프라인 소개 / 기타(직접 입력) |
| 알림 수신 동의, 마케팅 수신 동의   | 선택 | 동의한 시각을 기록                                                |
| 프로필 사진 직접 업로드            | 선택 | —                                                                 |
| 푸시 토큰                          | 선택 | 알림을 켠 기기에서 발급받아 저장                                  |

- 목적: 프로필 표시, 알림 발송, 유입 경로 분석
- 이름·휴대전화번호·이메일은 AES-256으로 암호화해 저장합니다.

### 앱 이용 중 생성되는 정보

- **반려동물 프로필** — 이름, 생년월일, 성별, 체중, 중성화 여부, 품종, 사진, 임종일, 공유 초대코드
- **추모관 댓글** — 작성자, 대상 추모관, 본문
- **댓글 신고** — 신고자, 대상 댓글, 신고 사유(선택지 + 직접 입력)
- **장례업체 후기** — 별점, 본문(암호화), 첨부 이미지
- **서비스 후기** — 본문. **암호화하지 않습니다**
- **이별 준비·응급 진행 상태** — 단계별 완료 여부, 체크한 준비물 등 진행 기록
- **미션 참여 기록** — 완료 여부, 첨부 사진, 음성 녹음(파일 URL·길이·형식·크기·파형)

### 랜딩 굿즈 설문 (익명)

로그인 없이 진행하며 무작위 응답 ID로만 식별합니다. 이름·연락처를 받지 않는 익명 조사입니다.

- 설문 답변 73문항, 일부 문항의 "기타" 직접 입력, 문항별 소요시간, 전체 응답 시간
- 유입 경로(UTM), 광고 클릭 식별자, 기기 범주(모바일·태블릿·데스크톱), 화면 크기, 언어, 시간대, 방문 식별자
- 선택 사연 12문항 — 전체 암호화 저장. 분석 동의와 공개 동의를 각각 따로 받고 동의 버전·시각을 함께 기록
- 목적: 서비스 수요 조사, 참여 흐름 개선

### 굿즈 발송 확정자

설문과 다른 테이블에 저장하며 아래 항목은 전부 암호화합니다.

- 보호자 이름, 연락처, 우편번호, 주소, 상세주소, 반려견 이름
- 굿즈 종류, 직접 제안 내용, 개인정보 동의 버전·동의 시각
- 반려견 사진 — 비공개 버킷에 저장. 공개 활용 동의 여부를 사진별로 기록
- 목적: 굿즈 제작·발송, 문의 대응

### 굿즈 보유 기간이 세 곳에서 다릅니다

- 신청 화면 동의 안내 — **"굿즈 발송일로부터 3주 뒤 삭제"**

- 서버 설정값 — **90일**

동의를 받을 때 고지한 3주가 가장 짧고 이용자에게 직접 보여준 문구라 기준이 됩니다.
어느 값으로 맞출지 정한 뒤 나머지를 고쳐야 합니다.

## 3. 제3자 제공 여부

**제공하지 않습니다.** 외부로 나가는 경로는 전부 처리위탁(호스팅·스토리지·푸시)이거나
광고·분석 도구로의 이전이며, 제휴사나 장례업체로 이용자 정보가 넘어가는 기능은 없습니다.
장례업체는 서비스가 보유한 목록을 보여주는 방향이고, 업체 쪽으로 정보가 나가지 않습니다.

- 메일·문자 발송 기능은 구현돼 있지 않아 관련 수탁사가 없습니다.

### 인프라 구성

| 구분           | 내용                                                            |
| -------------- | --------------------------------------------------------------- |
| 서버           | AWS EC2 (`t3.micro`), 서울 리전 `ap-northeast-2c`               |
| 데이터베이스   | 위 서버 안의 MariaDB 컨테이너 (직접 운영)                       |
| 이미지 저장소  | AWS S3 `pawever-images-prod` (서울 리전)                        |
| 굿즈 신청 사진 | AWS S3 `pawever-goods-survey-private-apne2-2026` (서울, 비공개) |
| 랜딩 호스팅    | Cloudflare Pages (`pawever-landing.pages.dev`)                  |
| API 도메인     | `api.pawever.kr` → 위 EC2 직결. Cloudflare를 거치지 않음        |

저장 위치가 모두 서울 리전이므로 회원·설문·굿즈 정보는 국내에 보관됩니다.
설문 응답과 굿즈 신청은 브라우저에서 `api.pawever.kr`로 직접 전송되며,
Cloudflare가 처리하는 것은 홈페이지 정적 페이지 요청과 그때의 접속 IP·브라우저 정보뿐입니다.

Cloudflare는 접속 시점에 따라 국외 서버가 사용됩니다. 한국에서 접속해도 `pawever.kr`은
미국(LAX) 노드로, `www.pawever.kr`은 인천(ICN) 노드로 연결되는 것을 확인했습니다.
접속 IP와 브라우저 정보가 국외에서 처리되므로 국외 이전에 해당합니다.

### 접속 기록

| 구분      | 내용                                                              |
| --------- | ----------------------------------------------------------------- |
| 기록 주체 | EC2 호스트의 nginx 1.24.0 (`api.pawever.kr` 앞단)                 |
| 형식      | 기본 combined 형식 — 별도 `log_format` 정의 없음                  |
| 기록 항목 | **접속 IP**, 접속 일시, 요청 경로, 응답 상태, User-Agent, Referer |
| 보관 기간 | **14일** (logrotate `daily` + `rotate 14`)                        |

요청 경로에 쿼리스트링이 그대로 들어갑니다. 14일치 로그 실측 결과입니다.

| 요청                        | 건수 | 로그에 남는 값 |
| --------------------------- | ---- | -------------- |
| `/api/users/nickname/check` | 12   | 닉네임         |
| `/api/funeral-companies`    | 12   | 위·경도, petId |

접속 IP와 같은 줄에 남아 결합됩니다. 좌표를 요청 본문으로 옮기거나 로그 포맷에서
쿼리스트링을 빼는 것이 개선 방향입니다.

애플리케이션(Spring) 로그에는 IP가 없습니다. 오류(4xx·5xx)나 3초 초과 요청만
요청 방식·경로·상태코드·소요시간·회원 식별번호로 기록합니다.

## 5. 파기 절차

### 회원 탈퇴 — 자동, 즉시

탈퇴 API를 부르면 아래가 한 번에 처리됩니다.

1. 이름·연락처·이메일·성별·생일·닉네임·소셜 회원번호·푸시 토큰을 즉시 비움
2. 회원 프로필 이미지 파일을 스토리지에서 삭제
3. 반려동물과의 연결(`user_pets`)을 삭제하고, 미션·이별 준비·응급 안내·장례업체
   진행 기록을 삭제
4. 반려동물 프로필 이미지 파일을 스토리지에서 삭제
5. 작성한 추모관 댓글은 **본문을 남기고 작성자 연결만 끊음**
6. 애플 로그인 사용자는 애플 계정 연동을 해제

**행 단위로 남는 것이 둘 있습니다.**

- `users` 행 — 식별 항목은 비워지고 가입일·탈퇴일·가입 경로 유형만 남습니다
- `pets` 행 — **삭제되지 않습니다.** 이름·생년월일·성별·체중·임종일이 그대로 남고,
  연결만 끊어집니다. 댓글·후기가 참조하는 외래키를 지키기 위한 처리입니다
  (`PetService.detachPetProfile`)

미션 녹음 파일은 DB 행이 지워져도 **스토리지에서 삭제되지 않습니다.** 회원 프로필과
반려동물 프로필 이미지만 지웁니다.

### 굿즈 배송 정보 · 2차 안내 이메일 — 수동

두 테이블 모두 삭제 예정일 칸은 있지만, 그 날짜를 보고 실제로 지우는
배치·스케줄러가 저장소 전체에 없습니다. 굿즈 신청은 배송 완료를 표시하는 코드도
아직 호출되지 않아, 지금 상태로는 삭제 예정일이 채워지지 않습니다.

방침에 기간을 쓰려면 그때까지는 담당자가 주기적으로 직접 지우는 운영 규칙이
있어야 실제와 어긋나지 않습니다.

### 파기 방법

- 데이터베이스 — 해당 값을 비우거나 행을 삭제. 복원 불가
- 파일 — 오브젝트 스토리지에서 객체 삭제
- 로그 — 보관 기간 경과 시 설정에 따라 자동 삭제

### 설문 응답은 본인 확인이 어렵습니다

이름·연락처를 받지 않는 익명 조사라, 응답자가 삭제를 요청해도 어떤 응답인지
특정할 방법이 사실상 없습니다. 굿즈를 신청한 사람은 연락처로, 2차 안내 신청자는
이메일로 찾을 수 있습니다.

> 방침에 "익명 설문 응답은 특정이 불가능해 개별 삭제가 어렵다"는 점을
> 미리 밝혀 두면 나중에 분쟁이 생기지 않습니다.

### 2차 안내 수신거부 창구가 없습니다

광고성 정보를 보내면서 수신거부 링크가 없으면 문제가 됩니다. 현재는 문의를 받아
사람이 처리하는 구조이므로, 최소한 발송 메일 안에 거부 방법과 주소를 명시하고
방침에도 같은 내용을 적어야 합니다.

## 8. 쿠키 · GA4 · GTM 등 자동수집 장치

### 자체 쿠키는 쓰지 않습니다

서비스가 직접 심는 쿠키는 없습니다. 대신 브라우저를 닫으면 사라지는 세션 저장소에
유입 경로, 페이지 체류시간, 설문 임시 답변을 담고, 화면 테마 설정만 로컬 저장소에 둡니다.
쿠키는 아래 외부 도구가 각자 심습니다.

| 도구               | 켜지는 조건                           | 보내는 정보                                                                  |
| ------------------ | ------------------------------------- | ---------------------------------------------------------------------------- |
| Google Analytics 4 | 측정 ID를 배포 환경변수에 넣었을 때만 | 유입 경로(UTM), 페이지 경로, 설문 진행 이벤트, 기기 범주·화면 크기, 체류시간 |
| Meta Pixel         | 픽셀 ID를 넣었을 때만                 | 페이지 조회, 설문 시작·완료, 신청 완료 시점, 광고 클릭 식별자                |
| Google Tag Manager | 컨테이너 ID를 넣었을 때만             | 이벤트 이름과 위 항목을 태그 도구로 전달하는 통로                            |

### 보내지 않는 것

**설문 답변, 이름, 연락처, 배송지, 반려견 사진은 어느 도구로도 나가지 않습니다.**
코드에서 차단하고 테스트로도 고정해 두었습니다.
Meta Pixel은 이메일·전화번호를 해시로 넘기는 고급 매칭 기능도 쓰지 않습니다.

### 사전 동의를 묻지 않고 바로 로드됩니다

접속하는 순간 분석·광고 동의를 자동으로 "동의함"으로 간주하고 GA4와 Meta Pixel을
바로 불러옵니다. 이용자가 선택할 화면은 없으며, 브라우저의 쿠키 차단 설정으로만
거부할 수 있습니다.
